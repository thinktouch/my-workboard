# 我的工作台

这是独立的本地应用，不依赖 ChatGPT、账号、在线托管或网络字体。

## 启动

Windows 双击 `启动工作台.cmd` 启动、双击 `关闭工作台.cmd` 关闭，也可以使用 `start.cmd` / `stop.cmd`。启动脚本优先使用本地 `runtime/node.exe`；若不存在，则使用系统安装的 Node.js 22.13 或更新版本。无需安装数据库服务或其他依赖。

Linux 安装 Node.js 22.13 或更新版本后，在项目目录执行：

```sh
sh start.sh
# 在另一个终端关闭：
sh stop.sh
```

Linux 脚本优先使用可执行的 `runtime/node`，否则使用系统 Node.js。启动保持前台运行，也可按 Ctrl+C 关闭。脚本支持从其他目录调用，项目路径可以包含空格。

跨平台也可直接运行 `node server.mjs` 启动、`node stop.mjs` 关闭，或使用 `npm start` / `npm stop`。

默认访问 <http://127.0.0.1:5173>。自定义端口：PowerShell 中执行 `$env:PORT=5273; .\start.cmd`，Linux 中执行 `PORT=5273 sh start.sh`。关闭脚本自动读取实际端口，无需再次设置 PORT。服务仅监听本机，不向局域网或互联网开放。

重复启动会显示现有服务地址。关闭脚本会验证当前项目的服务身份，完成正在处理的请求并关闭数据库后退出，不会按进程名或端口批量终止其他程序。未运行时关闭脚本会直接提示；异常退出产生的过期记录也会自动处理。旧版本服务需先关闭原窗口，再通过新脚本启动一次。

## 数据与迁移

- **真实数据在项目根目录的 `data.sqlite`**，与 `server.mjs` 同级。使用 Node 内置 SQLite，任务以关系表保存，状态、时间和回收记录都有独立字段。前端不使用 localStorage 保存任务。
- 每次修改在事务中提交，包含状态约束和索引；失败时整体回滚。使用 DELETE 日志模式和 FULL 同步，正常关闭后持久数据保存在一个数据库文件中。
- 首次创建数据库时，若同目录存在旧版 `data.json`，程序会自动迁移并逐项校验全部任务、时间、状态、回收站及版本号。原 JSON 不会被修改；数据库初始化成功后不再读取或写入 JSON，也不会重复迁移。
- 数据库损坏、旧 JSON 无效或迁移验证失败时会报错并保留原文件，不会静默清空或用旧数据覆盖数据库。
- 迁移到其他目录或设备前先关闭工作台，再复制整个项目目录，或复制 `data.sqlite` 到另一份相同版本项目的根目录。不要在程序写入期间直接复制数据库文件。
- 应用内没有文件上传、导入、下载、导出或压缩打包功能，也不再提供相关接口与脚本。

## 操作

- 顶栏左侧为名称，中间为任务输入，右侧为搜索和任务筛选；主要控件统一为 4px 圆角。
- 顶部输入任务，点击「立即行动 / 计划去做 / 灵活安排 / 暂时搁置」直接发送，没有独立添加按钮。Enter 发送至上次使用的象限，N 聚焦输入，`/` 聚焦搜索。
- 新任务保存成功后，会从输入区平滑飞入对应象限并轻轻落位，不阻塞继续输入。列表滚动、窗口变化或页面切到后台会结束飞行并恢复实际卡片；系统开启「减少动态效果」时直接显示任务。
- 每个象限内按添加时间从早到晚排序，新任务排在后面，完成状态和编辑不会改变先后顺序。任务按照文字长度自然排列，长文字自动换行；每个象限独立滚动，不撑长整页。
- 点击任务文字后，直接在同一行编辑。Enter 或点击其他位置保存，Esc 取消；编辑时没有象限类型控件。
- 创建时间和完成时间随任务保存在 `data.sqlite`。点击任务右侧三点，可原位查看精确到秒的创建时间；已完成任务同时显示完成时间，页面按北京时间展示。编辑内容或移动象限不会改动这些时间；恢复为待办后，当前完成时间清空，再次完成会记录新的时间。
- 三点按钮默认隐藏，鼠标移到任务上或键盘聚焦时显示，展开后可编辑、开始处理、完成、移动或删除。移动选项也在任务内展开，也可拖动任务跨象限移动。
- 三点菜单以统一 248px 宽度的下拉浮层显示，独立于任务列表，不改变卡片尺寸或挤动其他任务；靠近窗口边缘时自动避让，底部空间不足时向上展开。「移动」在同一个浮层内切换选项。点击外部、滚动任务列表或按 Esc 收起；支持方向键导航。任务列表按需更新当前条目，保留键盘焦点。完成框和三点按钮的点击区域均为 24×24px。
- 处理中任务显示轻量的蓝色状态标记，仍计入待办。可在三点菜单中恢复待办，完成后标记自动移除；状态随任务保存在 `data.sqlite` 中。
- 筛选顺序为全部、待办、处理中、已完成，默认选中全部。括号中显示各自的任务总数，新增和状态变化后自动更新。「处理中」只显示正在处理的任务，仍属于待办范围；在处理中视图新增任务时，会切换到待办以显示新任务。
- 操作成功后不显示提示条和撤销按钮，保存异常时原位显示错误及重试。历史删除记录仍保留在数据库中，通过 `deleted_at` 与原位置字段记录。页面不显示底部状态行。
- 点击筛选旁的「最近删除」文字按钮可从右侧滑出抽屉，顶部紧贴顶栏、底部到页面底边，四象限不会缩小或移动。抽屉独立于工作区容器，聚焦时不自动滚动页面。打开时背景蒙板淡入，顶栏和工作区不可操作，键盘焦点限制在抽屉内；点击蒙板、关闭按钮或按 Esc 可收起，动画结束后背景恢复操作，焦点返回入口。恢复后保留原任务的状态和时间。抽屉默认关闭，支持系统减少动态效果设置。顶栏名称、输入区与筛选沿同一中心线对齐，工作区采用白色面板、14px 任务正文与金属蓝坐标轴。
- 最近删除项的「删除」为永久删除，顶部「清空」可永久移除全部最近删除记录。两者都在抽屉内原位确认，可以取消，不使用弹窗。清空和永久删除不会影响正式任务；列表为空时清空按钮禁用。
- 编辑、移动、恢复和删除均在当前页面完成，不使用浏览器确认弹窗。

## Git 提交

仓库保留应用源码、当前使用的图标、测试、启动脚本和文档。历史截图、压缩包、设计预览及旧托管工程属于生成产物，不纳入 Git 提交。

`.gitignore` 排除了个人任务数据 `data.sqlite`、SQLite 日志、旧 JSON 数据及备份、本地 Node 运行时、服务状态记录 `.workboard-service.json`、临时文件和生成产物。克隆仓库后需准备 Node.js 22.13 或更新版本；首次启动自动创建空数据库。现有任务可在关闭工作台后通过复制本地 `data.sqlite` 迁移。

`.gitattributes` 统一源文件及 Linux 脚本使用 LF，Windows 批处理脚本使用 CRLF。
